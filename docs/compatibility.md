# 适配器与平台验证

Reqvia 的核心契约不限定运行平台。适配器负责接入具体请求器，并说明该实现可以交付哪些能力。Fetch 与 UniApp 是初期验证对象；其他 HTTP 实现通过同一 `Transport` 接口接入。

## 核心运行条件

主包输出 ES2022，使用 `Uint8Array`、标准 `URL`、`performance.now()` 以及 `setTimeout` / `clearTimeout`。运行环境需要提供这些标准能力，其中 `performance.now()` 用于不受系统时钟调整影响的调用预算。公开声明只依赖 ECMAScript 类型，不要求消费者启用 DOM 或 Node 类型。

Fetch 适配器另需应用注入 Fetch 实现和创建原生取消控制器的函数。核心运行条件与某个请求器的可用性分别验证。

## 能力边界

核心统一执行行为，适配器承接平台能够提供的报文。两类保证分别维护：

| 核心统一的行为           | 由环境与适配器决定的能力          |
| ------------------------ | --------------------------------- |
| 状态判断、解码、错误分类 | 可用 HTTP 方法与协议限制          |
| 调用快照、取消与总预算   | 物理取消是否真正停止网络工作      |
| 文本和字节的表示匹配     | 原生文本解码、二进制请求与响应    |
| 单次调用至多一次 `send`  | 重定向、代理、Cookie 与网络栈行为 |
| 中立响应结构             | 可观察的响应头与最终 URL          |

适配器已知无法满足请求时返回 `UNSUPPORTED`。意外的平台失败归为 `TRANSPORT`；返回内容违反中立报文契约时归为 `ADAPTER`。这些分类不保证能够识别所有平台内部原因。

## Fetch 适配

应用注入 `fetch` 与创建 `AbortController` 的能力。适配器按声明读取文本或字节，完成正文读取后再交付中立响应；获取响应头并不代表本次传输已经完成。

Fetch 的响应可能受到 CORS、受限响应头或不透明响应规则约束。适配器只保留平台实际暴露的信息；无法获得可用状态与正文的不透明响应不伪装成普通 HTTP 响应。文本解码结果与平台暴露的二进制正文分别处理；二者均不承诺保留 HTTP 报文框架或压缩传输字节。[Fetch 标准](https://github.com/whatwg/fetch/blob/main/fetch.bs)

响应最终 URL 仅在平台提供时填写。当前适配器构造接口接收 Fetch 实现与取消控制器工厂；定制 Cookie、代理或重定向时，由应用注入已明确配置的 Fetch 实现，不通过主包中的未知参数袋透传。浏览器与 Node 即使使用同名 Fetch 接口，也分别验证其环境约束。

## UniApp 适配

适配器显式接收 `uni.request` 所需能力。使用回调形式取得任务并连接取消，关闭自动 JSON 解析，让客户端解码器处理原始文本。原生参数、任务对象与回调类型只出现在适配器包中。

UniApp 官方文档中，`dataType` 默认是 JSON，响应表示及方法支持存在目标差异；成功回调没有统一的最终响应 URL 字段。因此适配器逐目标验证表示能力，缺失最终 URL 时省略该字段。[UniApp 请求接口](https://uniapp.dcloud.net.cn/api/request/request.html)

`timeoutMs: 0` 仅关闭 Reqvia 的总预算。平台请求器或网络仍可能自行超时；未由本次 Reqvia deadline 触发的底层超时按传输失败处理，保留原始原因。

## 验证矩阵

HTTP 核心与 Fetch 适配器已实现。当前真实网络测试运行于本机 Node，其他目标仍需各自验证；类型检查和构建通过不等于对应环境已经完成运行验证。

| 目标              | 文本请求与响应 | 字节请求与响应 | 状态与网络失败 | 物理取消 | 结果               |
| ----------------- | -------------- | -------------- | -------------- | -------- | ------------------ |
| 浏览器 Fetch      | 待验证         | 待验证         | 待验证         | 待验证   | 未验证             |
| Node Fetch        | 通过           | 通过           | 通过           | 通过     | 本地 HTTP 验证通过 |
| UniApp H5         | 待验证         | 待验证         | 待验证         | 待验证   | 未验证             |
| UniApp 微信小程序 | 待验证         | 待验证         | 待验证         | 待验证   | 未验证             |

App、其他小程序和其他运行时按接入进度增加行。真实支持范围还应注明运行时版本、开发工具或编译器版本、操作系统，以及开发工具或设备运行方式。

每次平台验证同时记录：

- 代码提交与适配器版本
- 环境、目标与执行命令
- 本地测试服务和用例范围
- 成功、失败、不支持或未验证的能力项
- 重定向、Cookie、响应头、字符编码等已观察到的限制

## 验证层次

内存传输用于验证核心控制流与 Service 行为；平台模拟用于验证参数与回调映射；真实网络用于验证完整正文与中断行为；设备或目标运行环境用于确认平台能力。每层结果只覆盖本层观察到的行为。

取消验证同时观察外层 Promise 和底层任务：前者应按核心契约结束，后者的停止行为作为适配器能力记录。对无法停止的物理工作，核心仍消费迟到结果并保持终态不变。

查询库组合在应用层验证。以 TanStack Query 为例，查询函数接收 `AbortSignal`，可通过兼容包传入 Service；绑定结束时释放监听。查询缓存、订阅和结果提交仍由查询层负责。[TanStack Query 取消指南](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)

## 当前验证记录

Node 本地验证使用 Node 22.22.2，测试服务只监听 `127.0.0.1` 的临时端口。执行 `vp run -F @reqvia/transport-fetch test` 可检查文本、字节、空正文、HTTP 失败、连接中断和慢正文期间的取消与超时。

`vp run verify:packages` 将两个产品包打成 tarball，在独立临时项目中离线安装，校验主包的纯 ECMAScript 声明与 Fetch 的原生类型，并运行同一份 Service 的内存和真实网络调用。该验证不引用工作区源码路径。
